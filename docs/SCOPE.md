## 4. Tech Stack ที่ใช้ได้ **[วิชา]** (อาจารย์กำหนดเพียงว่า "ตามที่เรียนเท่านั้น")

### Frontend (วิชา Client)

- React ผ่าน **Create React App** (`react-scripts`) ตัวแปรแวดล้อมต้องขึ้นต้นด้วย `REACT_APP_`
- **React Router v6** (`react-router-dom@6`): `Routes`, `Route`, `Link`, `NavLink`, `useParams`, nested route + `Outlet`, `Navigate`, `useNavigate`, `useLocation`
- **Tailwind CSS v3** (`tailwindcss@3 postcss autoprefixer`) ห้ามใช้ v4 เพราะ CRA ไม่รองรับ
- State/Effect: `useState`, `useEffect`, `useContext` (`AuthContext` + `useAuth()`)
- เรียก API ด้วย **`fetch`** ผ่านฟังก์ชันกลาง `apiFetch` ใน `src/api/`
- Test: **Jest + React Testing Library** (`@testing-library/react`, `dom`, `jest-dom`, `user-event`) รันด้วย GitHub Actions
- Deploy บน Vercel พร้อม `vercel.json` (rewrite ทุก path ไป `index.html`)

### Backend (วิชา Server + ตัวอย่างต่อระบบในวิชา Client)

- ภาษา **Go** ใช้ `net/http` (`http.NewServeMux()`) ตามตัวอย่างต่อระบบ
- PostgreSQL ผ่าน `github.com/jackc/pgx/v5` (`pgxpool`)
- รหัสผ่านใช้ `golang.org/x/crypto/bcrypt`, JWT ใช้ `github.com/golang-jwt/jwt/v5`, อ่าน `.env` ด้วย `github.com/joho/godotenv`
- โครงโฟลเดอร์ที่สอน: `store/`, `handler/`, `mw/` และ middleware `Logging`, `CORS`, `RequireLogin`, `RequireRole`

### Database / Deploy ที่สอน

- Supabase: ใช้ **Session pooler (พอร์ต 5432, IPv4)** ไม่ใช้ Transaction pooler (6543) และ **เปิด RLS ทุกตาราง**
- Render: Web Service ภูมิภาค Singapore, Build `go build -o app .`, Start `./app`, ตั้ง Health Check Path, อ่าน `PORT` จาก env
- Vercel: ตั้ง `REACT_APP_API_URL` แล้วต้อง **Redeploy** ทุกครั้งที่แก้ค่า
- Backend จำลอง (Node/Express) ใช้ได้เฉพาะช่วงพัฒนา ห้ามเป็นส่วนของระบบที่ Deploy

### ไม่อยู่ในเนื้อหา **[เสนอ]** → เสี่ยงผิด "ตามที่เรียนเท่านั้น" ห้ามใช้ถ้ายังไม่ถามอาจารย์

ORM, React Query/SWR/Redux, ไลบรารี UI (MUI, Ant ฯลฯ), ไลบรารีกราฟ/แผนที่, การอัปโหลดไฟล์, ระบบชำระเงิน, WebSocket/Realtime, Gin, TypeScript, Next.js

## 5. ขอบเขตงานที่ต้องส่งมอบ

### 5.1 ฟังก์ชันระบบ

อาจารย์ระบุเพียงว่า: **[จารย์]** ต้องมี Guest, Member, Admin / ระบบสมาชิกต้องมี Register, Login/Logout, Profile, เปลี่ยน Password / ฟังก์ชันหลักต้อง "ครบกระบวนการ" และ Backend ต้องตรวจสิทธิ์
รายละเอียดด้านล่างเป็นรูปแบบที่ใช้ในตัวอย่างวิชา **[วิชา]** หรือข้อเสนอ **[เสนอ]** ที่ต้องปรับตามหัวข้อ

**Guest (ยังไม่ login)**
- ดูข้อมูลสาธารณะ ค้นหา/กรอง ดูรายละเอียดได้ **[เสนอ]**
- Register และ Login **[จารย์]**
- หน้าที่ต้อง login ถูกพาไป Login พร้อมจำหน้าเดิม **[วิชา]**

**Member**
- Register, Login/Logout, ดู/แก้ Profile, **เปลี่ยน Password** **[จารย์]**
- ฟังก์ชันหลักที่ต้อง login (ตัวอย่างวิชา: เขียน/ลบรีวิวของตัวเอง, ให้คะแนน, บันทึกรายการ) เลือกตามหัวข้อ **[วิชา/เสนอ]**
- ทำได้กับข้อมูลของตัวเองเท่านั้น: Backend อ่านว่าเป็นใครจาก token ห้ามรับ `memberId` จาก body/URL **[วิชา]**

**Admin**
- ต้องมีส่วน Admin และ Backend ตรวจสิทธิ์ **[จารย์]**
- Dashboard สรุปตัวเลข, ตารางจัดการข้อมูลหลัก (ค้นหา + เพิ่ม/แก้ไข/ลบ พร้อมกล่องยืนยันก่อนลบ), จัดการสมาชิก/เปลี่ยนบทบาท (Admin เปลี่ยนบทบาทตัวเองไม่ได้) **[วิชา: Week 12]**
- Admin คนแรกตั้งด้วย SQL ไม่มี endpoint สมัครเป็น admin **[วิชา]**

### 5.2 กติกาที่ต้องผ่าน (จุดที่วิชาเน้นและน่าจะตรวจ)

- Backend ตรวจสิทธิ์ **[จารย์]**; "ซ่อนปุ่มใน React ไม่ใช่การป้องกัน" ทุกสิทธิ์ที่ซ่อนต้องมี Go ตอบ **403** คู่กันและทดสอบด้วย `curl` **[วิชา]**
- `401` = ไม่รู้ว่าเป็นใคร, `403` = รู้ว่าเป็นใครแต่ไม่มีสิทธิ์ ตรวจตั๋วก่อนแล้วค่อยตรวจบทบาท **[วิชา]**
- มี Loading / Empty / Error **[จารย์]**; ใช้ `status` ตัวเดียวและมีปุ่มลองใหม่ **[วิชา]**
- เปลี่ยน state ฝั่ง React หลัง server ตอบสำเร็จเท่านั้น และไม่ mutate state **[วิชา]**
- Backend ตรวจข้อมูลซ้ำเสมอแม้ฟอร์มตรวจแล้ว **[วิชา]**
- ห้ามมีค่าลับใน repo (`.env`, `JWT_SECRET`, รหัสฐานข้อมูล) **[วิชา]**

### 5.3 Unit Test (React)

- ต้องมี Test ที่ตรวจพฤติกรรมสำคัญ, Assertion ถูกต้อง, รันผ่าน **[จารย์]**
- ใช้ Jest + React Testing Library และรันผ่าน GitHub Actions (`npm ci` → `npm test -- --watchAll=false` → `npm run build` ด้วย `CI=true`) **[วิชา]**
- ขอบเขตที่เสนอให้ครอบ: `apiFetch`, ฟอร์มสำคัญ, `ProtectedRoute`/`RequireRole`, หนึ่งหน้าที่โหลดข้อมูล (loading/error/ลองใหม่) **[เสนอ ตามตัวอย่าง Week 10 และ 12]**

### 5.4 โครงสร้างโปรเจกต์

- FE/BE แยกหน้าที่ตามที่เรียน, ชื่อชัดเจน, แยกคำตั้งต้น **[จารย์]** (ดูหมายเหตุใต้ตารางเกณฑ์ในข้อ 3)
- Frontend `src/components`, `src/pages` (รวม `src/pages/admin`), `src/api`, `src/auth`; Backend `store/`, `handler/`, `mw/` **[วิชา]**
- **ให้ใช้ชื่อโฟลเดอร์ตามที่เรียนเท่านั้น** (รายการข้างบน) ไม่ตั้งชื่อเอง เพราะเกณฑ์ระบุ "ตามที่เรียน" **[เสนอ]**
- `docs/api.md` (สัญญา API) และ `README.md` บอกวิธีรัน/URL ระบบจริง **[วิชา: Week 9 และเช็กลิสต์ Week 12 ไม่ใช่ข้อบังคับของ Term Project]**

### 5.5 Deploy

- Frontend Vercel, Backend Render (เชื่อม Repo), Database Supabase **[จารย์]**
- ลำดับ Supabase → Render → Vercel, env `DATABASE_URL`, `JWT_SECRET`, `ALLOWED_ORIGINS` (Render) และ `REACT_APP_API_URL` (Vercel, ห้ามมี `/` ปิดท้าย), CORS ตรงทุกตัวอักษรห้ามใช้ `*`, ปลุก Render ก่อนสาธิต **[วิชา]**

### 5.6 คลิปสาธิต (ไม่เกิน 15 นาที)

- เห็นระบบที่ Deploy จริงทำงานครบ, ทุกคนอธิบายโค้ดส่วนตัวเองพร้อมระบุชื่อ, อธิบายรับข้อมูล → API → ผลลัพธ์, มีหลักฐานการแก้ปัญหาจากงานจริง **[จารย์]**
- เล่าอย่างน้อย 1 เรื่อง "พังตรงไหน แก้ยังไง" และเส้นทางกดปุ่ม → React → `apiFetch` → Go → DB → กลับมา **[วิชา: เช็กลิสต์ก่อนนำเสนอ Week 12 สอดคล้องกับเกณฑ์ข้อ "เหตุผลและการแก้ปัญหา"]**

## 7. กติกาทำงานผ่าน GitHub และการใช้ AI **[เสนอ ทีมแก้ได้]**

- repo นี้เป็น **private** ทำงานผ่าน branch และ Pull Request ไม่ push ตรงเข้า `main` หลัง setup แรก
- แบ่งงานเป็นขอบเขตที่ไม่แก้ไฟล์เดียวกัน และทุกคนต้องอธิบายส่วนที่ตัวเองรับผิดชอบในคลิปได้
- ใช้ AI ได้ แต่คนที่ commit ต้องอธิบายโค้ดได้ทุกบรรทัด ถ้า AI เสนอเครื่องมือนอกข้อ 4 ให้หยุดและถามทีมก่อน
- ห้ามนำเนื้อหาของอาจารย์ขึ้น repo โฟลเดอร์ `เนื้อหาที่เรียน(ต้องใส่ .gitignore)/` ถูกกันไว้ใน `.gitignore` แล้ว
- ห้าม commit ค่าลับ ใช้ `.env` และตัวแปรบน Render/Vercel
