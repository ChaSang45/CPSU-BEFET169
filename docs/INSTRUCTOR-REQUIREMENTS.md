# ขอบเขตงาน Term Project BE-FE (CPSU-BEFET169)

> เอกสารนี้คัดลอกจากข้อกำหนดของอาจารย์เท่านั้น (ข้อความประกาศ + ตารางเกณฑ์ที่อาจารย์ส่งมา)
> ไม่มีข้อมูลที่ทีมเพิ่มเอง ถ้าต้องเพิ่มหรือตีความเพิ่ม ให้ใส่ในไฟล์อื่น
> ที่มา: ประกาศของอาจารย์ในกลุ่ม ลงวันที่ 7 พ.ย. 2569

---

## ประกาศเรื่อง Term Project วิชา BE-FE

- แต่ละทีมสร้าง Web Application อะไรก็ได้ที่ตัวเองสนใจ **ยกเว้น Web หนังแบบที่ทำตอนเรียน**
- ขอบเขตที่ต้องมี คือ
  1. ส่วนหน้า Web (หรืออาจเรียกว่าหน้าร้าน) ต้องมีส่วนของการเข้าชมแบบ **Guest** และส่วนของการเข้าชมแบบ **Member**
  2. ต้องมีส่วนของ **Admin**
- Tech Stack ต้องเป็นไปตามที่เรียนเท่านั้น และใช้วิธีการตรงกับเนื้อหาที่เรียนเท่านั้น
- ส่วน Frontend ต้อง Deploy บน **Vercel** ส่วน Backend ต้อง Deploy บน **Render** แบบเชื่อมกับ Repo และ Database Deploy บน **Supabase**
- เกณฑ์การให้คะแนน (เต็ม 20 คะแนน) ตามตารางด้านล่าง
- กำหนดส่งงาน วันที่ **8 – 14 พฤศจิกายน** โดยจะ Post Form วันที่ 8

## เกณฑ์ประเมิน Term Project BE-FE

React + Fetch API • Go • รวม 20 คะแนน

- ผลงานกลุ่ม 13 คะแนน
- คลิป 7 คะแนน (35%)

### ส่วนที่ 1 ผลงานกลุ่ม — 13 คะแนน

| หัวข้อ | เต็ม | ได้ครึ่งหนึ่ง | 0 คะแนน |
|---|---|---|---|
| **Tech Stack / Deploy (2)** | ตรงตามที่เรียน • Vercel / Render เชื่อม Repo / Supabase ครบ | ถูกต้องบางส่วน หรือ Deploy ไม่ครบ | รันตรวจไม่ได้ |
| **ระบบสมาชิก (2)** | Register, Login/Logout, Profile, เปลี่ยน Password ได้จริง | ทำงานได้บางฟังก์ชัน | ใช้งานไม่ได้ |
| **Guest / Member / Admin (4)** | ฟังก์ชันหลักครบกระบวนการ • Backend ตรวจสิทธิ์ | ฟังก์ชันไม่ครบ หรือสิทธิ์ยังไม่ครบ | ไม่มีฟังก์ชันหลักที่ใช้ได้ |
| **API / Database / UI (2)** | Fetch → Go → Database จริง • มี Loading / Empty / Error | เชื่อมต่อได้บางส่วน หรือจัดการสถานะไม่ครบ | เชื่อมต่อไม่ได้ |
| **React Unit Test (1)** | ตรวจพฤติกรรมสำคัญ • Assertion ถูกต้อง • รันผ่าน | มี Test ที่ตรวจได้ แต่ยังไม่ครบหรือผ่านบางส่วน | ไม่มี Test ที่ตรวจได้ |
| **Project Structure (2)** | FE/BE แยกหน้าที่ตามที่เรียน • ชื่อชัดเจน • แยกคำตั้งต้น | แบ่งโครงสร้างแล้ว แต่หน้าที่ยังปนกัน | ไม่จัดโครงสร้างตามที่เรียน |

คะแนนระดับกลาง = ครึ่งหนึ่งของคะแนนเต็มแต่ละหัวข้อ

### ส่วนที่ 2 การอธิบายผ่านคลิป — 7 คะแนน

| เกณฑ์ | เต็ม | ระดับกลาง | เริ่มต้น / ไม่มีหลักฐาน |
|---|---|---|---|
| **สาธิตระบบจริง (ทีม) • 2** | 2: ระบบ Deploy จริง • เห็นกระบวนการและผลลัพธ์ครบ | 1: สาธิตได้บางส่วน | 0.5: เห็นแค่หน้าจอ / 0: ไม่สาธิต |
| **โค้ดและเส้นทางข้อมูล (รายบุคคล) • 3** | 3: ชี้โค้ดจริง • อธิบายรับข้อมูล → API → ผลลัพธ์ได้ถูกต้อง | 2: เข้าใจเส้นทางหลักแต่รายละเอียดไม่ครบ | 1: บรรยายโค้ดแต่เชื่อมโยงไม่ได้ / 0: ไม่อธิบาย |
| **เหตุผลและการแก้ปัญหา (รายบุคคล) • 2** | 2: อธิบายเหตุผล • มีปัญหาและหลักฐานวิธีแก้จากงานจริง | 1: อธิบายได้แต่หลักฐานไม่ครบ | 0.5: เล่ากว้าง ๆ / 0: ไม่แสดงความเข้าใจ |

### ข้อกำหนดทีมและคลิป

1. ทีมละ 2 คน (บางทีมมี 3 คน)
2. คลิปไม่เกิน 15 นาทีต่อทีม ทุกขนาดทีม
3. ทุกคนต้องอธิบายโค้ดส่วนที่ตนรับผิดชอบ พร้อมระบุชื่อ
4. แบ่งเวลาอธิบายให้เหมาะสมกับจำนวนสมาชิก

ประเมินความเข้าใจและหลักฐาน ไม่ให้คะแนนความสวยของคลิป

### สรุปคะแนน

**คะแนนแต่ละคน = ผลงานกลุ่ม 13 + สาธิตทีม 2 + อธิบายรายบุคคล 5 = 20**
